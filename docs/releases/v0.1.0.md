# Paperboy v0.1.0

Released 2026-10-31. Status: alpha. This is the first public cut of the open engine.

Paperboy reads your Google Search Console, picks what to write from your own data, researches and writes it, checks every claim against the exact source text it saved while researching, publishes it, and measures what happens next. This release puts that loop, a self-host server, a CLI and an MCP server in one repository under AGPL-3.0.

## Highlights

- **The full loop is open.** Topic selection with a SERP-strength gate, research, writing, the fact check, publishing, Search Console sync and the rank loop.
- **A fact check you can read.** Rule checks first (numbers must appear in the cited source, links must point at pages that were read, banned claims are matched exactly), then a judge. Every article ends in VERIFIED or HELD with the quoted sentence, the problem and the fix. A held article gets one fix pass, then it is checked again, and if it still fails it is not published. Method: [docs/fact-check.md](../fact-check.md).
- **One-command self-host.** Docker Compose starts Postgres, a migration job (it runs on every start), the API server and a worker. Nothing is spent on your Anthropic key until you ask for an article, and a passed article waits for your `publish`.
- **A CLI and an MCP server that agents can drive.** `paperboy` has a stable `--json` mode, `paperboy check` exits 1 on a failed check so it works in CI, and `paperboy mcp` serves the same operations as tools over stdio.
- **Hard cost caps.** An article that would cross 6 web searches, 1.50 USD or 600,000 tokens (defaults in `packages/engine/src/config/models.ts`) is stopped and held for review.

## Known limits

- **Alpha.** Expect rough edges, and expect the API and schema to change before 1.0.
- **The CLI is not on npm.** Run it from source (see below). Do not use `npx paperboy`: the unscoped npm package of that name is a different project.
- **No web app in this repository.** The hosted blog on a subdomain, the paste-in prompt feed and the dashboard are part of Paperboy Cloud. On a self-host, publish to WordPress, Ghost or the signed webhook, and set the target with `POST /api/v1/sites/{id}/publishing`.
- **Baseline fact check on self-host.** The calibrated verifier, cross-site learning and billing are closed and only in the cloud. Self-host uses Claude Haiku 4.5 with your own key, or the open word-overlap `RuleJudge` with no key.
- **Writing uses Claude and its web search tool.** There is no model-agnostic layer.
- **Search Console needs your own Google OAuth client** on a self-host (scope `webmasters.readonly`).
- **CI workflows are parked in `ci-workflows/`** because the token that created the repository could not push workflow files, so pull requests are not checked automatically yet. Run `npm run typecheck`, `npm test` and `npm run scrub` locally.

## Install

Self-host:

```bash
git clone https://github.com/paperboyseo/paperboy.git && cd paperboy
cp .env.example .env  # set ANTHROPIC_API_KEY, the passwords, PAPERBOY_ADMIN_EMAIL, PAPERBOY_ADMIN_PASSWORD
docker compose up --build
```

CLI from source (Node 22 or newer):

```bash
npm ci --prefix packages/cli && npm run build --prefix packages/cli
alias paperboy="node $PWD/packages/cli/dist/cli.js"
paperboy connect https://your-site.com --self-host http://localhost:3000
```

Details: [docs/self-host.md](../self-host.md).

## Upgrade

There is nothing to upgrade from: this is the first release. For later releases:

```bash
docker compose exec db pg_dump -U postgres paperboy > backup.sql   # back up first
git pull
docker compose up --build -d   # the migrate job applies new migrations
```
